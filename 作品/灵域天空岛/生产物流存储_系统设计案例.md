# 《灵域天空岛》系统设计：生产 · 物流 · 存储

| 项 | 内容 |
|---|---|
| 项目 | 2D 沙盒自动化同人独立游戏 |
| 角色 | 策划负责人 |
| 时间 | 2025.09 – 至今 |
| 说明 | 公开精炼版，写三块系统当时怎么想清楚的；不是完整内部 GDD |

---

## 1. 我想先解决什么感觉

沙盒自动化很好玩，也很容易滑向「铺满传送带、微操带速」。我自己玩这类游戏时，真正让我停不下来的，往往是：**产线匹不匹配、配方怎么拼、堵了能不能一眼看懂再调。**  
做《灵域天空岛》时，我就想把长期乐趣按在这几件事上，而不是按在「带子越来越快」上。

于是问题变得具体：生产、物流、存储如果搅在一起，规则会互相打架，程序也不好接，玩家更学不会。前期还得能手工玩起来，中后期又要能长成产线。失配的时候，反馈得可读——我隐约觉得，用「带速等级」硬造深度，玩久了会假。

---

## 2. 想清楚边界之后，规则才好写

我花了不少时间才敢下笔写细则，因为先要承认三件事各管一段：

生产负责**把东西变成别的东西**（配方、时序、停工）。物流负责**搬走、堵住、把压力传回去**。存储负责**保管和界面里的整理**，不发生转换。

一句话是后来才收束出来的：生产改物品，物流移物品，存储管物品。

```text
采集 / 加工设施 ──产出──▶ 物流通路（单格缓冲）──▶ 下游设施 / 容器
         ▲ 反压停工 ◀── 缓冲满 / 下游拒收
```

边界清楚以后，很多「这算哪边的规则」就不吵了。

---

## 3. 生产：我想要一根统一的骨架

我希望所有生产设施共用一套配方、端口、时序、停工逻辑，差异尽量进配置——不然每来一个熔炉、一个合成台就另写一套，后面一定会裂。

成长上我想同时照顾两头：前期近身手工就能做出工具和设备；中后期用持续产中间件，再用「指定次数」做装备或设备本体。工业量产和玩家偶尔要的那几件成品，如果规则完全两套，我自己都会晕，所以后来收成**同一套规则、两种用法**：持续跑中间件，指定次数做成品。

输入口容量跟「当前配方这一槽单次用量」走，而不是跟堆叠上限走——这是我想了之后才觉得对的：没选配方就不该收货，选了配方，口的意义是「这一次制作要吃掉多少」，不是又一个小仓库。停工则统一接缺料、输出受阻、次数用尽，并和物流反压对上。

大类共用 UI 和操作，等级只改速率、配方权限、端口数这类配置，是为了以后扩内容时还撑得住。公开材料里我没有把各大类细则清单摊开，内部还有不少「待填」；求职场景里摊半成品，反而像没做完。

---

## 4. 物流：策略我想放在匹配上

拖拽把输出口连到输入口，通路自动长出来——这点我想保留直觉。真正纠结的是：要不要给通路自己的额定带速？

我想过「带速科技」那种成长，后来放弃了。因为我更在意的是上下游产能是否匹配；如果再叠一层带速，玩家会把精力耗在微操带子上，和我想要的乐趣拧着。所以通路**不设独立额定产能**，畅通时跟得上就跟，跟不上就在缓冲里堆，堆满就反压，上游停工，通路变红——堵塞要能读、能解，比如把缓冲里的东西拿走。

一带一种、单格缓冲、上限对齐存储单格，也是为了让物流和「往箱子里放一格」的感觉一致，少学一套新语言。跨岛仙台、大型多口传送仓这些，我知道以后可能要，但这一版先标成预留，免得和当前验收缠在一起。

---

## 5. 存储：先把「不转换」守住

存储侧我先把职责钉死：只保管、只整理界面（选中、半选、交换这类），不执行配方。和生产的差别，说透就是一句话——容器不转换，设施才转换；接上物流以后，端口仍然不转化物品，容量按堆叠上限理解。

UI 细则可以慢慢磨，我不想让它挡住产线规则先冻结。多口仓库、跨界大型传送仓储，和物流远期接口一起想更合适，现在硬写进存储正文，命名和职责容易糊。

---

## 6. 现在到哪一步

三块的边界、生产通用规则、物流通路与反压、存储职责，这些我已经能讲圆，也写进可评审的文档里了。各大类生产 UI/配方细表、存储接物流的正文合并、可玩 Demo 里的手感，都还在做。早期和大纲口径不一致的操作稿、以及大段「待填」章节，我不拿来当公开材料。
