## 1. 项目目标与约束

部门要做员工个人年度总结 H5：用交付、协作数据让人感到这一年被看见。上级希望并行看到多套完整想法再选型。

- 载体：手机竖屏 H5（9:16）。
- 语气：鼓励、认可；禁止考核压迫与无必要横向攀比。
- 数据：业务底稿 + 部分飞书字段；公开仓库不写真实姓名、业绩、地域等明细。
- 交付阶段：已完成口径冻结、三版选型、第二版执行基线文档（策划案 v1.1 + 美术资源需求表 v1.1）、可点原型；**未进入正式开发上线**。

## 3. 第二版是什么（以 v1.1 执行为准）

第二版正式名称：**小羊观影 · 部门年度总结报告**。  
内容基准：《小羊观影·分页台本》v2.0；执行文档日期 2026-08-04。

### 3.1 一句话体验

员工进入电影院，与「小羊」一起观看银幕上播放的个人年度工作故事，最后生成可分享的年度明信片。

### 3.2 固定主流程

```text
Loading → Home → S0（小羊入场）
  → P01–P11（身份 / 交付 / 项目 / 岗位 / 经理 / 外场 / 沟通 / 年度CP / 文档 / 会议 / 年度之最）
  → P12 年度高光（五项全 0 则跳过）
  → P13 致谢收束
  → P14 小羊明信片
```

| 阶段 | 页面 | 体验任务 |
|---|---|---|
| 开场 | Loading、Home、S0 | 加载、建立观影概念、小羊带入场 |
| 数据故事 | P01–P11 | 按固定顺序讲身份、交付与协作 |
| 庆祝与收束 | P12–P13 | 有高光则庆祝，再用小羊台词收束 |
| 留念 | P14 | 生成只含年度摘要的可分享明信片 |

### 3.3 页面结构（A / B / C）

策划案明确三类内容页（Loading 为系统初始化，不入三类）：

| 类型 | 适用 | 结构要点 |
|---|---|---|
| A 影院宽景 | S0、P12、P13 | 全屏影院/收束场景；角色为场景形象 |
| B 数据展示 | P01–P11 | 银幕主题画面 + 两侧头像对话 + 底部说明框 |
| C 功能页 | Home、P14 | 开始观影 / 生成分享明信片 |

特殊镜头：P01 以 A 开场，拉近后进入 B；P12 从 B 缩回 A。

### 3.4 配置拆分（方便程序对接）

| 配置 | 内容 |
|---|---|
| Page_Config | 页面顺序、构图、状态、分支、引用 |
| Data_Config | 字段与显示条件 |
| Copy_Config | 旁白、台词、分支文案 |
| Art_Config | 资源 ID → 文件；由 `assets[]` / bundle 引用 |

原则：程序不靠文件名猜用途；动态姓名/数字/城市等**不得烘焙进美术资产**。

### 3.5 策划案职责边界（重要纠偏）

v1.1 策划案定义的是**执行基线**：流程、数据逻辑、交互、配置、低保真槽位。  
**明确不负责**：美术风格、画风、配色、渲染方式、AI 绘图工具/模型/Prompt、最终视觉定稿。

配套《美术资源需求表 v1.1》只列「需要什么素材、用于哪里、资源 ID」，同样不锁画风。视觉方向另走样张评审。

> 因此公开总结里，不再把早期探索 Demo 的某一套画风写成「策划案已锁定的最终美术」。早期本地 Demo 是探索与对齐工具；**当前正式口径以 v1.1 文档为准**。

### 3.6 关键分支（脱敏摘要）

| 页 | 规则 |
|---|---|
| P02 交付 | 超越比例满足条件才追加比较句 |
| P05 经理 | 有记录列次数；无记录保留本页给鼓励，不跳页 |
| P06 外场 | 0 次走出差现场分支 |
| P08 年度 CP | 必须主动点击揭晓后才能继续 |
| P12 高光 | 五项全 0 整页跳过；有数据才庆祝 |

## 4. 我怎么迭代（第二版）

迭代不是一次写完文档，而是「问题 → 规则 → 文档/原型 → 再验收」循环。

### 4.1 迭代主线

| 轮次 | 我遇到的问题 | 我怎么改 |
|---|---|---|
| 选型 | 上级要多套完整想法，不是改语气 | 先冻数据口径与信息主题，再并行三版读法 |
| 叙事对齐 | 早期探索线观影感弱 / 信息易被演出抢走 | 收敛为影院叙事；把「数字可读」写成信息层级与避让规则 |
| 工程化 | 口头方案程序接不住 | 拆成 Page/Data/Copy/Art 四配置 + 资源 ID；出美术需求表对接 |
| 分支完备 | 经理 0 次、出差 0 次、无高光等边缘态 | 写入台本与策划案分支表（如 P05 不跳页、P12 可跳过） |
| 原型验证 | 只看文档难判断节拍与点击 | 用 AI 搭可点原型站，按流程走 Loading→明信片 |

### 4.2 一次具体迭代：从「好看」拉回「可执行」

| 步骤 | 内容 |
|---|---|
| 现象 | 探索期容易把风格、镜头、文案缠在一起，评审难判断哪一层出错 |
| 判断 | 第二版要对齐的是「读法与规则」，风格应可替换 |
| 动作 | 在 v1.1 把职责切开：策划案管流程/数据/交互/配置；美术表只管资源 ID 与分层；风格留给样张 |
| 结果 | 程序可以按 ID 对接；AI 出图不会被误写成硬性规范 |

## 5. AI 协作：怎么用、边界在哪

重点不是「AI 写了多少字」，而是：**我负责决策与验收，AI 负责加速可替换层。**

### 5.1 协作分工

| 我拍板 / 验收 | AI 辅助加速 |
|---|---|
| 产品目标、禁区语气、数据口径与分支 | 按既有结构扩写文档段落、对齐表格格式 |
| 页面流程、A/B/C 结构、交互状态机 | 生成低保真槽位说明、检查清单草稿 |
| 配置字段、资源 ID、美术/程序边界 | 按需求表批量起草资源清单与命名建议 |
| 样张取舍、是否写入正式规范 | 生成探索向美术资产 / 风格样张（**不自动升格为硬性要求**） |
| 原型是否覆盖主流程与关键点击 | 搭建可点原型站、加快页面串联与演示 |

### 5.2 三个真实用法

**① 提高写文档效率**  
把已定口径喂给模型，让它按「每页：目标—数据—布局—文案—交互—分支—资源」填表。我再删套话、补分支、改冲突。  
反例：模型曾滥写收束金句、重复「这一年」→ 我加禁区与频次上限，最终以台本 / v1.1 定稿为准。

**② 辅助生成美术资产（探索层）**  
用 AI 快速出背景、角色、UI 底板候选，方便对齐「影院叙事是否成立」。  
同步在美术需求表写清：动态文字不进图、资源按 ID 交付、**画风不由策划案锁死**。避免把 AI 偶然出图写成程序/美术硬约束。

**③ 搭建可点原型**  
把流程与关键交互落到可点原型，用来走通 Loading→明信片、P08 揭晓、P12 跳过等高风险点。  
公开原型：  
https://sheep-cinema-annual-report.blush-nova-6933.chatgpt.site/  
（ChatGPT Site，访问需登录；面试可投屏演示。）

### 5.3 AI 边界（写进 v1.1 的那条）

策划案原文口径：不把「AI 绘图工具、模型、工作流或 Prompt」写成策划案职责；也不把未经确认的 AI 建议写成美术硬性要求。  
我的执行原则：**AI 产出默认是草稿；进正式文档必须经过口径/分支/验收清单过滤。**
