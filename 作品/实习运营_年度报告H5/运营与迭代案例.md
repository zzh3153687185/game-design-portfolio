## 1. 这件事要做什么

部门需要一份给员工个人看的年度总结 H5：用交付和协作相关数据，让人觉得一年被看见、被记下**；同时要给上级几套完整方案做选择，而不是只交一版终稿。

当时比较在意几件事：同一份数据底稿能不能做出真正不一样的方案；温情和数据感怎么共存（别做成考核或攀比）；AI 怎么用才稳、才交得出去；每版是否够完整，上级能不能直接评。

---

## 2. 怎么推进的

### 2.1 工作顺序

没有从零聊天直接生成终稿，而是按阶段往下走：

1. 先梳理数据底稿（字段、展示、排序）  
2. 做第一版：顺便把文档格式和可复用的设计偏好写清楚  
3. 第二、三版复用同一套骨架，主要换主题和表现形式  
4. 最后做对比，方便上级选  

第一版最重要的不只是「做出一版」，而是把格式和偏好沉下来，后面两版才好改得动、改得快。

### 2.2 逐渐定下来的偏好

主题延续「被看见」的温情，语气鼓励认可、不施压。信息上数字先跳出来，再跟短叙述和收束句。载体是手机竖屏 H5。文案上避开考核感、排名焦虑和套话堆砌。文档体例上，一屏先放原型分区图，再写规则说明，方便和设计、开发对齐。

### 2.3 三版差在哪

| 版本 | 读起来的感觉 | 相对固定的部分 |
|---|---|---|
| 第一版 | 温情直述：引导句 + 数据 + 收束 | 浏览顺序、数据口径、系统规则 |
| 第二版 | 更偏场景/叙事感，和第一版拉开距离 | 同上 |
| 第三版 | 主信息在文本框里，每屏最多一条小 Tips；气氛交给背景图 | 同上 |

换的是「怎么读」，不是「数据说什么」。

### 2.4 和 AI 怎么分工

我负责框架、各版核心思路、禁区和口径拍板、消化上级意见、最终取舍。AI 按任务卡扩写、对齐已定思路、改文案和结构、协助同步原型与文档。敏感数据不进公开材料；第二、三版开写前先有「设计思路总结」，避免每版各写一套格式。

## 3. 遇到的麻烦和怎么处理

| 情况 | 怎么处理 |
|---|---|
| 多版容易变成换皮 | 让三版在结构和辅文形态上就不同（直述 / 叙事感 / Tips），立意也分开写 |
| 数据口径容易漂 | 先冻结数据说明，各版只引用；要改就改底稿 |
| 温情文案容易假 | 定禁区和句式；限制套话出现次数；一屏只讲一件事 |
| 反馈散落在多轮沟通 | 版本号管理，策划案留版本记录，用对比表帮助选择 |
| AI 偶尔跑偏语气或占位名 | 任务卡 + 思路总结双约束，人工过一遍规则和禁区 |
| 跨职看不懂散文式说明 | 用原型定分区，规则区只写显隐和交互 |

---

## 4. 最终留下了什么

- 数据说明  
- 第一版完整策划案（含多轮定稿）和设计思路总结  
- 第二、三版平行方案  
- 线框/原型与逐屏标注  
- 分阶段工作流，方便交接  

中间改过不少次：文案禁区、雷达等可视化规则、某些数字的展示条件，都是评审里一点点定下来的；也保留过归档，方便回退。

这不是游戏上线运营，但确实练了写清规则、跟多方对齐、按反馈改版本，以及把 AI 放进可控流程里用。
