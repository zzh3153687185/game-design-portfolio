## 1. 设计起因与目的

### 1.1 业务背景

部门需要一份面向员工个人的年度总结 H5：用交付与协作相关数据，让同事感到一年被看见、被记录**，同时供上级在「主题 × 表现形式」上做选择，而不是只交一版定稿。

### 1.2 我要解决的问题

1. **同一数据底稿，如何产出可对比的多方案？**（避免「同一方案改三遍」）  
2. **如何在温情认可与数据专业感之间取平衡？**（禁考核压迫、禁同事横向攀比焦虑）  
3. **如何让 AI 协作可控、可复用、可交接？**（多 Agent / 多阶段，而不是一次性聊天生成）  
4. **如何支撑上级评审？**（每版完整可评：主题、形式、逐屏规则、验收点）

### 1.3 成功标准（当时自定）

| 标准 | 含义 |
|---|---|
| 三版平行 | 思路不同，而非文案微调 |
| 口径统一 | 数据字段、显隐、分支规则跨版可复用 |
| 可评审 | 上级能直接看懂差异与适用场景 |
| 可落地 | 策划案体例对齐「一屏一图 + 规则说明」，便于设计/开发 |

## 2. 过程中的思考

### 2.1 先定工作流，再写内容

把任务拆成串行阶段，而不是从零聊天生成终稿：

1. **数据底稿梳理** → 统一字段、展示方式、排序  
2. **第一版** → 定文档格式 + 提炼可复用的「设计思路总结」  
3. **第二 / 三版** → 复用思路骨架，只替换主题与表现形式核心  
4. **汇总对比** → 供上级择优  

关键判断：**第一版的价值不只是「做出一版 H5」，而是沉淀格式与设计偏好，让后两版 marginal cost 下降。**

### 2.2 设计偏好（从评审中收敛）

| 维度 | 收敛结果 |
|---|---|
| 主题基调 | 延续「被看见」温情；鼓励认可，不施压 |
| 信息层级 | 核心数字高亮 → 短叙述 → 收束句 |
| 载体 | 移动端 H5 竖屏翻页 |
| 禁区 | 考核感、排名焦虑、贬低缺项、堆砌黑话/排比 |
| 体例 | 参照游戏策划案习惯：**每屏 = 原型图 + 文字规则**（便于跨职对齐） |

### 2.3 三版如何真正「平行」

| 版本 | 核心差异（表现形式/调性） | 不变的部分 |
|---|---|---|
| 第一版 | 被看见 · 温情直述；引导句 + 数据 + 收束 | 浏览序、数据口径、系统规则 |
| 第二版 | 更偏沉浸/叙事或轻互动取向（与第一版拉开场景感） | 同上 |
| 第三版 | 轻松锦囊 · 主文本框 + 每屏 ≤1 条 Tips；氛围交给背景图 | 同上 |

思考点：**换的是「怎么被阅读」的体验，不换「说什么数据」的事实层**——这与系统策划里「表现层可变、规则层稳定」是同一类分层。

### 2.4 AI 协作怎么用才不算甩锅

- 我负责：框架初稿、核心思路输入、禁区与口径拍板、多轮上级反馈消化、定稿取舍。  
- AI 负责：按任务卡扩写策划案、对齐设计思路总结、批量改文案/结构、辅助原型与文档同步。  
- 约束：先写「设计思路总结」再开第二、三版，避免每版另起一套格式；敏感数据不进公开作品集。

## 3. 遇到的困难与解决方案

| 困难 | 为什么难 | 解决方案 |
|---|---|---|
| 多版容易做成「换皮」 | 同一主题改语气，上级仍觉得没得选 | 强制三版在**结构/辅文形态**上差异化（直述 / 叙事感 / Tips），主题立意也分开写清 |
| 数据口径易漂 | Excel 字段多，屏与屏条件分支多 | 先冻结《数据说明》，各版只引用、不私自改口径；变更走底稿 |
| 温情文案易套话 | 多屏重复「这一年」「很棒」会假 | 定文案禁区与句式规范；引导句配额；一屏一事 |
| 评审反馈碎片化 | 上级意见散落在多轮对话 | 定稿版本号管理（v1.x）；策划案带版本记录；对比表服务择优 |
| AI 产出不稳定 | 易跑偏语气或泄露占位名 | 任务卡 + 设计思路总结双约束；人工过禁区与分支规则 |
| 跨职理解成本 | 设计/开发需要分区而非散文 | 采用「原型图定分区 + 规则区写显隐/交互」的策划案体例 |

## 4. 产物与迭代结果（公开可说部分）

### 4.1 已交付类型

- 数据说明（字段、展示、排序）  
- 第一版完整策划案（含多轮定稿迭代）+ 设计思路总结  
- 第二、三版平行策划案  
- 线框/原型图与逐屏标注（支撑评审）  
- 多阶段工作流文档（便于交接）  

### 4.2 迭代特征（对应「维护与反馈」能力）

- **同目标多方案**：不是线性改一版，而是并行三套供选择。  
- **评审驱动收敛**：文案禁区、可视化规则（如雷达、超越比例展示条件）在反馈中逐步拍板。  
- **版本可回滚/可对比**：保留定稿链与归档，错误线可重启而不丢上下文。

### 4.3 与系统策划岗位的迁移点（如实表述）

本项目不是游戏系统上线运营，但锻炼了岗位说明书里相近的能力：

| 岗位常见要求 | 本项目中的对应 |
|---|---|
| 写功能/方案文档 | 逐屏规则、全局系统规则、验收要点 |
| 跨职跟进 | 策划体例服务设计/开发理解；原型定分区 |
| 基于反馈迭代 | 多轮上级修改、版本迭代、对比择优 |
| AI 提效（加分） | 受控的多阶段 AI 协作，而非一次性生成 |
